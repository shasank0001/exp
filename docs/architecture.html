01The map

Everything in the system lives in exactly one of three zones. Arrows show the only allowed directions of control.

Design rule: the renderer can never reach sideways into the filesystem, processes, or credentials. Every privileged act passes through a named, validated IPC method — and the agent itself can never launch runs or approve anything.

02Sandboxed renderer

Vite + React 19 + TypeScript, built to static files. It renders threads, streams replies, and shows diffs, logs, and tool activity — all as text.

Can do

Call the 20 bridge methods · subscribe to engine events · render text, charts of real data, and diffs · hold local UI state (panels, drafts, polling).

Cannot do

No Node APIs · no fetch · no dynamic code · no HTML rendering of agent output · sending blocked until project trust + engine availability.

03Privileged main process

Electron main owns windows, the custom protocol, all IPC validation, the engine host, and shutdown. One instance only.

  1. Isolated session. Dedicated partition, all permissions denied, downloads blocked, popups denied, navigation locked to the app entry.
  2. Custom protocol. mlcopilot://app/… serves only desktop/ + variants/ presentation assets with a strict Content-Security-Policy. Main and preload code are never servable.
  3. Validated IPC. Every handler checks sender + main frame + exact entry URL. Thread ids match /^[A-Za-z0-9_-]{1,64}$/; paths must be absolute existing directories.
  4. Graceful shutdown. Re-entry guarded; run escalation (TERM → KILL → persisted) and adapter stops are awaited before exit.

04Pi adapter — the swappable seam

Spawns the pinned Pi binary in RPC mode and translates its protocol into the app's event kinds. This is the seam another engine (Codex, Claude) would plug into.

Protocol facts (verified against Pi 0.73.1)

Strict LF JSONL framingRequest/response id correlationprompt / abort / get_stateAuth failures classifiedagent_settled unreliable → finalize on agent_endApproval requests auto-declined, shown as error

Sessions persist per thread via --session-dir; HOME is inherited so Pi reads the user's real settings and auth. Model resolves from MLCOPILOT_MODEL or Pi's configured default (OpenRouter nex-agi/nex-n2.5-mini:free).

05Supervised runs

One owned local process at a time. Launched only by the UI button — the agent has no launch path.

No sandbox is claimed. Runs execute as you with full privileges. Safety is structural: explicit launch, cwd forced to the thread's project, single-flight, 4-hour wall time, process-group kills that can never touch foreign processes, and an env allowlist (tuning vars only — PATH, LD_PRELOAD, HOME rejected).

06Data on disk

All durable state lives under the OS user-data directory — never in the repo, never in the cloud.

~/.config/ml-copilot/            (Linux userData)
├── records/
│   ├── threads.json             # thread list (atomic writes, corruption → quarantined backup)
│   ├── messages-<thread>.jsonl  # append-only transcript (bad lines skipped)
│   ├── tools-<thread>.jsonl     # bounded tool-activity log with rotation
│   ├── trust.json               # per-project trust (atomic, quarantined)
│   └── runs/
│       ├── <runId>.log          # captured stdout/stderr (8 MiB cap, tail-loss flagged)
│       └── <runId>.json         # command, status, exit code, timestamps
└── engine-home/<thread>/sessions/  # Pi native sessions (context survives restarts)
